# Robywire

Daily robotics news site. Astro + MDX, static output, no CMS — the repo is the
database and git is the write API.

```bash
npm install
npm run dev      # http://localhost:4321
npm run build    # -> dist/
npm run preview  # serve dist/
```

---

## How publishing works

An automation commits an MDX file to `src/content/news/`. CI builds and deploys.
There is no admin, no API, no database.

```
src/content/news/<slug>.mdx   ->   https://robywire.com/news/<slug>
```

The full contract is in `docs/content-contract-v2.md`. The short version:

```yaml
---
title: "Headline"
description: "One sentence, 155 characters or fewer."
publishedAt: 2026-08-24
updatedAt: 2026-08-25              # optional
categories: [humanoids, funding]   # 1–3, closed vocabulary
format: news                       # news | explainer | launch | field-notes
featured: false
author:
  name: "Name"
  avatar: "/img/authors/name.png"  # optional
image:                             # optional whole block
  light: "https://..."
  dark: "https://..."
  aspectRatio: "16/9"
  credit: "Figure"
  creditUrl: "https://figure.ai/press"
---
```

**The schema is enforced at build time.** A category outside the vocabulary, a
description over 155 characters, or a missing byline fails `npm run build` with a
message naming the file and field. That is deliberate: a bad commit should never
reach production, and an automation that can't produce valid frontmatter should
find out in CI rather than on the live site.

### Adding a beat

Beats are a closed list in `src/consts.ts`. Add to `BEATS`, and the schema, the
`/topics` index and the beat page all pick it up on the next build. Do not add one
just because a post doesn't fit — a category with one post in it reads as
abandonment.

## Routes

| Route | Source |
|---|---|
| `/` | `src/pages/index.astro` — lead story + latest + beats |
| `/news` | `src/pages/news/index.astro` — page 1 of the archive |
| `/news/page/2` … | `src/pages/news/page/[page].astro` — pages 2+ |
| `/news/<slug>` | `src/pages/news/[slug].astro` |
| `/topics` | all beats and tags, with counts |
| `/topics/<beat>` | one beat |
| `/about`, `/404` | static |
| `/rss.xml` | full feed |
| `/sitemap-index.xml` | generated by `@astrojs/sitemap` |

**Beat pages live under `/topics/`, not `/news/`.** The content spec originally
proposed `/news/<beat>`, which collides with `/news/<slug>` — a post slugged
`humanoids` would be ambiguous. `/topics/` removes the class of bug entirely.

Page 1 of the archive is served at `/news` only. The paginated route deliberately
skips page 1 so `/news/page/1` never exists as duplicate content, and page 2's
"newer" link points back at `/news`.

### Reserved slugs

`page` cannot be used as a post slug — see `RESERVED_SLUGS` in `src/consts.ts`.

## Design system

`src/styles/global.css` holds the whole thing: tokens at the top, components below.
Swiss grid and typographic discipline, Linear/Vercel surface craft.

- **Accent** — Instrument blue. Five `--accent-*` steps plus `--on-accent`.
- **Themes** — dark default, separately designed light theme. Defined in three
  blocks (`:root`, `prefers-color-scheme: light`, `[data-theme="light"]`). Edit all
  three together or a colour will fail in one of the states.
- **Theme switch** — three states: system, light, dark. Stored in `localStorage`
  under `rw-theme` and re-applied before first paint by an inline script in
  `Base.astro`. Keep that script inline and in the head, or you reintroduce a flash
  of the wrong theme on load.
- **Contrast** — every text pair clears WCAG AA 4.5:1 in both themes. The muted mono
  labels are the tightest at ~4.7:1; if you lighten `--gray-9` or `--gray-10`,
  re-check them.

## Newsletter

The subscribe form is deliberately inert — it shows a "not connected" message rather
than silently swallowing addresses. To wire it up, give the `<form>` in
`src/components/Subscribe.astro` a real `action` and remove the `data-newsletter`
attribute that triggers the placeholder.

## Images

Remote URLs only, never files in the repo. `images.unsplash.com` is allow-listed in
`astro.config.mjs`; add any other host there.

Preference order is press-kit image with credit → no image → stock. The `image`
block is optional and the layouts handle its absence.

`image.dark` is served via `<picture>` with a `prefers-color-scheme` media query, so
it follows the operating system rather than the manual theme switch. If that matters
later, it needs a small script; for now, most posts should set only `image.light`.

## Deploying

Static output in `dist/`. Any host works — Netlify, Vercel, Cloudflare Pages,
GitHub Pages. No build command beyond `npm run build`, no server runtime, no
environment variables.

Point the host at the repo and set the publish directory to `dist`.
